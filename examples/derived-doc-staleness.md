# Case Study: Stale Detection for Derived Documents (Content Hash, Materiality, and a Guard Against Thinner Regeneration)

## The Problem
A set of derived documents (a one-page summary and a long report per subject, each generated by a model from a maintained source page) was refreshed whenever a date check said the source was newer. The check compared the source's frontmatter `updated:` date to the newest date found inside the derived documents. Two failures followed:

1. **Timestamps lie.** Any mechanical pass over the source (cleanup, lint fixes, index sync) bumps `updated:` without changing content, so a bulk pass flags every subject at once. One refresh costs about **86K tokens** (13 measured runs, 72K to 95K), so a false bulk alarm is over 1M tokens of avoidable work.
2. **A refresh only reads its source, so it is lossy when the source is thin.** Regenerating from an 11 KB source over a richer 18 KB document would have shrunk it, and two subjects had already come out at about 9 KB reports against 20 to 35 KB for healthy peers.

## The Solution
1. **Stale means content changed, not date changed.** Each output folder carries a one-line sidecar `<12-hex sha256 of the source body> <date> <source bytes>`, written by the refresh step. The check recomputes the hash of the current source body (frontmatter stripped, line endings and trailing spaces normalized). A sidecar file rather than text inside the documents, because the document converter copies HTML comments into the rendered file.
2. **Materiality.** A hash change alone still fires on a one-line monitoring note, so flag only when dated entries appeared after the documents' date or the source size moved 5% or more.
3. **A guard against regressing.** Before regenerating, compare source size to the existing report. Below 0.9x, stop and recommend rebuilding the source first (measured: healthy sources were 1.08 to 1.35x their report, thin ones 0.52 to 0.63x). Keep a `.prev` copy for one cycle.
4. **Check the outputs, not the process.** Skill instructions can be skipped or run from an older cached copy, so the session-start check also lints results: the summary has its 10 headings and no evidence tags, the report keeps its tags, the rendered files are newer than their markdown, a `.prev` exists only with a sidecar, and the report is not 25% or more smaller than `.prev`.
5. **Peer-relative thin check.** A source under 0.5x the median source size is flagged even when its own report is equally thin (thin sources were 0.33 to 0.41x the median, healthy ones 0.72x and up).
6. **Weekly nudge with a price tag.** The check is silent when clean, nudges at most weekly unless the flagged set changes, and prints `N flagged, about N x 86K tokens`.

## Results
| Metric | Before | After |
|---|---|---|
| Stale trigger | source `updated:` date vs newest date in docs | body hash + (new dated entries or 5% size change) |
| False flags from one-line notes | 6 subjects flagged | 0 (about 516K tokens of nudged refresh work avoided) |
| Lossy refreshes | 2 would have overwritten richer documents | 2 blocked by the guard (about 172K tokens) |
| Thin source found | after refresh, by reading the output | at the first session, by the peer-median check |
| Cost when nothing is wrong | n/a | 0 tokens (silent) |

Cost to fix thin sources once found: about **1.62M tokens for four subjects, roughly 400K each** (research 493K, folding notes into the source 381K, re-reading previously blocked pages 391K, regenerating 353K), against 86K for a plain refresh from a healthy source. That gap is the argument for catching a thin source early.

## Bugs Caught by Dogfooding
1. **Case-only matching silently skipped a subject.** Source slug `acme-desk` never matched folder `AcmeDesk`, so that subject was excluded from the check entirely. Fixed by normalizing both sides (`[^a-z0-9]` removed).
2. **Inline hash stamp leaked into the rendered documents.** An HTML comment at the end of each markdown file appeared in the converter's output. Moved to a sidecar.
3. **First dry run of the output lint fired 28 times on a healthy set.** Unnumbered `## Heading` styles broke a numbered-heading rule, and file times were newer than the renders because of an earlier clean-up edit. Fixed the rule (count `##` headings) and re-rendered.

## Honest Limits
- **No saving on the first run.** Every source had genuinely changed, so date and hash rules agreed; the savings are prospective (bulk false alarms, blocked lossy refreshes).
- **Padding is not detectable.** One regeneration added an appendix explicitly "to get above the old size". Legitimate and padded report/source ratios overlap (0.93 to 0.997), so this is handled by instruction (size is not a target) and by the `.prev` and shrink flag, not by a check.
- **Thresholds are data-fit** to one set (0.9 guard, 0.5 peer, 5% size, 25% shrink); re-measure on a new corpus.

## Tokenminning Principles Applied
| Principle | How |
|---|---|
| **Eliminate context debt continuously** | Refreshing only on content change stops paying to regenerate unchanged documents |
| **Design systems not prompts** | Checks are a script run at session start and a helper the skill calls, not a paragraph the model may skip |
| **Retrieve don't preload** | The nudge reads a one-line sidecar and file sizes, never the documents |
| **Compress don't repeat** | Sidecar hash replaces re-reading the source to see whether it changed |
