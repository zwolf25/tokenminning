# Case Study: Wiki Pipeline — sc-wiki-builder → sc-wiki-cleanup

**Before:** $50+/run, 11 subagents, full-vault audit by default  
**After:** ~$15-25/run, 2-3 subagents, recently-touched scope by default

---

## Context

Two skills run back-to-back on the shared SC Product Management Second Brain vault:

- **sc-wiki-builder** — synthesizes raw notes into wikis (17 raw files → 12 wikis touched, 1 new)
- **sc-wiki-cleanup** — audits wikis for quality issues (full vault: 92 wikis + 24 market-research docs)

The cleanup skill defaulted to full-vault scope because no narrower scope existed. The builder run *produced* the exact 12-file list of what changed — the cleanup skill just didn't use it.

---

## Root Causes (A–G)

| ID | Cause | Tokenminning Technique Violated |
|----|-------|----------------------------------|
| **A** | Cleanup defaulted to full-vault scope; only two scopes existed (single-wiki or entire vault). No target specified → silently ran expensive path. Created the 11-agent fleet. | **Retrieve, don't preload** — retrieval as query planning |
| **B** | Ignored own skill's 15K-char threshold rule. Two files (~18K each) full-Written instead of targeted Edit. Rationalized "content already in context." | **External indexing** — content loaded twice (Bash cat + Read) |
| **C** | Double-ingested 3 large files. Bash `cat` preview, then harness `Read` (required before Edit/Write). ~18K chars paid 2–3× each. | **External indexing** — load once, just-in-time |
| **D** | Improvised mandatory "fact fingerprint" from all 11 subagents. Never cross-referenced in synthesis. Cost paid twice: generate + ingest. | **Structured memory over dumps** — dump nobody reads back |
| **E** | ~25 individual grep+Edit pairs for a single mechanical change (timestamp bumps). Each carried fixed tool-call overhead. | **Compaction at source** — batch mechanical edits |
| **F** | Scheduled task (`sc-wiki-builder-weekly`) carried stale 37-line fallback procedure (pre-manifest, pre-threshold-awareness). Unattended runs = more expensive + lower quality. | **Eliminate context debt continuously** |
| **G** | Five content issues (contradiction, 3× repeated phrasing, arithmetic error, misattribution, ambiguous cross-ref) caught at audit time. A cheap targeted re-read at authoring would have caught them for a fraction of cost. | **Compaction at source** — self-check where written |

## Fixes Applied (4 Files)

| File | Changes |
|------|---------|
| `sc-wiki-builder/SKILL.md` | Closed 15K threshold loophole (B); banned Bash cat previews before Edit/Write (C); added Step 5.7 self-check before stamping raw files processed (G); added batch-mechanical-edit guidance (E). |
| `sc-wiki-cleanup/SKILL.md` | Added third scope tier: **recently-touched** (seeded from prior builder run's file list, one-hop via `topics:`). Full-vault now reserved for `--full`/explicit request (A). Banned mandatory fact-fingerprints unless named cross-batch check needs one (D). "Omit empty sections" applies to every dimension, not carve-outs (D). Batch-mechanical-edit guidance (E). |
| `sc-wiki-builder-weekly/SKILL.md` | Rewrote 37-line duplicated fallback → 10-line thin wrapper that fails loudly instead of running stale logic (F). |
| `sc-monthly-wiki-cleanup/SKILL.md` | Added `--full` flag since default scope changed (A). |

## Mapping to Tokenminning Principles

| Principle | Applied Here |
|-----------|--------------|
| **Retrieve, don't preload** | Fix A — only 12 wikis relevant, not 92. The builder run *produced* the query plan; cleanup just needed to consume it. |
| **Compress, don't repeat** | Fix D — eliminated unused fingerprint dump generated by 11 agents and never read. |
| **Structure, don't narrate** | Fix E — batched 25 mechanical edits into 1–2 structured passes. |
| **Eliminate context debt continuously** | Fix G — Step 5.7 self-check at authoring catches contradictions before they become audit findings. |
| **Design systems, not prompts** | Fix A — scope architecture (3 tiers + explicit flag) replaced implicit default. |
| **Optimize context, not complexity** | Fix C — removed double-ingestion anti-pattern without adding complexity. |
| **Spend tokens where reasoning matters** | Fix A — tokens now spent on *changed* wikis (high signal) not *all* wikis (low signal). |

## The Pattern: Retrieval as Query Planning

This case study concrete-izes **"retrieve, don't preload"** at the *skill architecture level*:

```
BEFORE (Tokenmaxxing default):
  User runs cleanup → skill defaults to FULL_VAULT → 92 files → 11 agents → $50

AFTER (Tokenminning default):
  User runs cleanup → skill reads builder-output.json → seeds RECENTLY_TOUCHED (12 files) → 2–3 agents → $15
  User wants full audit → explicit --full flag → FULL_VAULT → 11 agents → $50 (intentional)
```

**Key insight:** The "query plan" (which files to audit) was *already computed* by the upstream skill. The downstream skill just needed to accept it as input instead of re-deriving the expensive default.

This generalizes: **any multi-skill pipeline should pass the relevant-file list forward as a first-class artifact**, not leave each skill to independently guess scope.
